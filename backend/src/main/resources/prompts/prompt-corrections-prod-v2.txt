## 1. IDEMPOTENCE WEBHOOK TWILIO (CRITIQUE)

Problème : Si Twilio renvoie le même message deux fois (retry sur timeout), on le traite deux fois = doublon de message en base + double appel Anthropic + double réponse WhatsApp au prospect.

Fichier : backend/src/main/java/fr/leadrevive/outreach/controller/WebhookController.java

Correction :
- Ajouter un cache Caffeine pour stocker les MessageSid déjà traités (TTL 10 minutes)
- Au début de la méthode qui reçoit les webhooks WhatsApp entrants, vérifier si le MessageSid a déjà été vu
- Si oui, retourner 200 OK sans traitement
- Si non, l'ajouter au cache et continuer normalement

Exemple de cache à ajouter dans le controller :
```java
private final Cache<String, Boolean> processedMessages = Caffeine.newBuilder()
    .expireAfterWrite(Duration.ofMinutes(10))
    .maximumSize(10_000)
    .build();
```

Dans la méthode webhook :
```java
String messageSid = request.getParameter("MessageSid");
if (messageSid != null && processedMessages.getIfPresent(messageSid) != null) {
    return ResponseEntity.ok().build(); // Déjà traité
}
if (messageSid != null) {
    processedMessages.put(messageSid, true);
}
```
